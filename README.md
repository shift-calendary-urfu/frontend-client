# Календарь смен — frontend

React + TypeScript + Vite. Доступны вход, регистрация, настройки профиля, управление ПВЗ и сотрудниками, календарь смен, создание и редактирование смен, удаление расписания и копирование на выбранные даты.

## Быстрый запуск через Docker

Установите и запустите [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/) с Linux-контейнерами. Node.js, npm, Python и uv на компьютере для этого способа не нужны. Первая сборка требует подключения к интернету.

Нужны два проекта команды: этот frontend и актуальный **backend-server из ветки `dev`**. Команды выполняются из корня соответствующего проекта.

### 1. Запустить backend и PostgreSQL

Если backend уже работает на порту `8000`, переходите к следующему шагу.

В папке **backend**, рядом с `docker-compose.yaml`, создайте `.env` по его инструкции. Для новой локальной базы можно использовать:

```env
POSTGRES_USER=shift_user
POSTGRES_PASSWORD=local_dev_password
POSTGRES_DB=shift_calendary_db
POSTGRES_PORT=5433
```

Это пример для локальной разработки. Если база уже существует, используйте её прежние реквизиты. Не заменяйте существующий `.env` примером: новые значения не меняют пароль ранее созданной базы.

Из папки **backend**:

```powershell
docker compose up --build -d
docker compose logs -f backend
```

В актуальном backend запуск PostgreSQL, установка зависимостей и применение миграций автоматизированы. Дождитесь запуска Uvicorn, затем откройте [http://localhost:8000/docs](http://localhost:8000/docs). `Ctrl+C` завершает просмотр логов, контейнеры продолжают работать.

### 2. Запустить frontend

Из папки **frontend**, где лежат `Dockerfile`, `compose.yaml` и `package.json`:

```powershell
docker compose up --build -d
```

Docker установит зависимости через `npm ci` и запустит Vite. Откройте **[http://localhost:3000](http://localhost:3000)**. Создавать `.env` frontend для стандартного Docker-запуска не требуется.

Frontend обращается к API через `/backend`. Vite направляет эти запросы на `http://host.docker.internal:8000`, убирая префикс `/backend`. Это работает и с backend из его Docker Compose, публикующим порт `8000` на компьютере. Добавлять `/api/v1` не нужно.

Если backend запускается вручную через uv, он должен слушать `0.0.0.0`, чтобы принимать подключения из контейнера:

```powershell
uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### Логи, повторный запуск и остановка

Все команды ниже — из папки frontend:

```powershell
# Посмотреть состояние и логи
docker compose ps
docker compose logs -f frontend

# Повторно запустить без пересборки
docker compose up -d

# После изменений кода, зависимостей или Dockerfile пересобрать образ
docker compose up --build -d

# Остановить frontend и удалить его контейнер
docker compose down
```

Исходники копируются в образ при сборке, поэтому изменения файлов на компьютере требуют пересборки. `Ctrl+C` при просмотре логов не останавливает сервис. Backend и база запускаются и останавливаются отдельно, из папки backend; для их остановки без удаления контейнеров используйте `docker compose stop`.

### Настройки frontend

При необходимости создайте `.env` рядом с `compose.yaml`, скопировав `.env.example`. В PowerShell:

```powershell
if (-not (Test-Path .env)) {
    Copy-Item .env.example .env
}
```

| Переменная                                               | Назначение                                                                                              |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `DOCKER_BACKEND_URL`                                     | Адрес backend из контейнера; по умолчанию `http://host.docker.internal:8000`.                           |
| `BACKEND_URL`                                            | Адрес backend для запуска frontend через npm; по умолчанию `http://127.0.0.1:8000`.                     |
| `VITE_API_BASE_URL`                                      | При запуске через npm — префикс API, по умолчанию `/backend`. В Docker Compose зафиксирован `/backend`. |
| `VITE_SUPPORT_URL`, `VITE_PRIVACY_URL`, `VITE_OFFER_URL` | Необязательные публичные ссылки; пустые значения оставляют соответствующие элементы неактивными.        |

Например, если backend опубликован на порту `8001`, в `.env` frontend укажите:

```env
DOCKER_BACKEND_URL=http://host.docker.internal:8001
```

После изменения `.env` для Docker выполните `docker compose up -d --force-recreate frontend`. Не указывайте `localhost` или `127.0.0.1` в `DOCKER_BACKEND_URL`: внутри контейнера это сам frontend.

У frontend и backend разные `.env`. Пароли PostgreSQL и JWT-секреты не нужны frontend. `.env` и его локальные варианты исключены из Docker-образа; Compose передаёт только перечисленные в `compose.yaml` настройки.

## Локальная разработка без Docker для frontend

Этот вариант удобен для редактирования интерфейса с автоматическим обновлением страницы. Нужен Node.js **24.15+ в ветке 24** или **22.22.2+ в ветке 22**; npm устанавливается вместе с ним. Backend и PostgreSQL должны быть запущены отдельно.

Из папки frontend в PowerShell:

```powershell
if (-not (Test-Path .env)) {
    Copy-Item .env.example .env
}
npm.cmd ci
npm.cmd run dev
```

В `.env` для этого способа используются:

```env
VITE_API_BASE_URL=/backend
BACKEND_URL=http://127.0.0.1:8000
```

Откройте [http://localhost:3000](http://localhost:3000). После изменения `.env` перезапустите Vite. В Bash/macOS/Linux используйте `npm` вместо `npm.cmd`. Не запускайте Docker-версию frontend одновременно: обе используют порт `3000`.

## Проверка работы

1. Зарегистрируйтесь и войдите — откроется список ПВЗ.
2. В «Настройках» измените имя, сохраните и обновите страницу: данные должны сохраниться.
3. Создайте ПВЗ с непустым адресом и проверьте его редактирование.
4. Зарегистрируйте аккаунт сотрудника в другом браузере или окне инкогнито.
5. В сессии владельца добавьте сотрудника по точному телефону, проверьте его появление в описании ПВЗ и в разделе «Сотрудники» нижнего меню.
6. Измените роль и должность, затем проверьте отмену и подтверждение удаления.
7. Откройте «Календарь» в нижнем меню или «Открыть календарь смен» в описании ПВЗ. Выберите точку, месяц и день.
8. В нижней панели дня нажмите «Добавить сотрудника», выберите активного сотрудника и время, кратное 30 минутам. Для редактирования нажмите его цветную полосу на шкале времени.
9. Нажмите «Размножить смены», выберите исходные смены на шкале времени и целевые даты в календаре, затем «Сохранить». Проверьте появление копий.
10. Проверьте отмену и подтверждение удаления отдельной смены, всех смен сотрудника за день и всего дня. Зайдите обычным сотрудником: доступен просмотр, а управление скрыто.

Управлять сотрудниками могут владелец и администратор конкретного ПВЗ; сотрудник может просматривать список. ФИО и телефон меняются в настройках своего аккаунта. Подробности — в [docs/EMPLOYEES.md](docs/EMPLOYEES.md).

Управлять сменами могут владелец и активный администратор ПВЗ. При создании смены выбирается существующий сотрудник; при редактировании текущий API позволяет менять только время. Копирование добавляет смены и сохраняет существующие записи. Полный список экранов, запросов, ограничений и изменённых файлов — в [docs/CALENDAR.md](docs/CALENDAR.md).

Календарь оформлен по пяти присланным макетам: цветные блоки с именами, нижние панели дня и редактирования, шкала времени и отдельный экран копирования. Данные загружаются из API; системные часы и индикаторы телефона отображает само устройство.

## Сборка и тесты

Без локального Node.js, при запущенном frontend-контейнере:

```powershell
docker compose exec frontend npm test
docker compose exec frontend npm run build
```

Либо локально:

```powershell
npm.cmd test
npm.cmd run build
```

Сборка создаёт `dist/` там, где выполняется команда: в контейнере или на компьютере. Vitest использует подменённые ответы API и не требует запущенного backend.

Для отдельных браузерных тестов при локальной установке зависимостей:

```powershell
npx.cmd playwright install chromium
npm.cmd run test:e2e
```

Playwright запускает frontend на порту `3000`, если он ещё не работает. Ответы API в этих тестах также подменяются.

Для сравнения оформления без backend при запущенном `npm run dev` откройте `/tests/visual/calendar-host.html?screen=calendar`. Параметр `screen` принимает `calendar`, `day`, `add`, `edit`, `copy`. Это отдельные тестовые страницы размером 393 × 852 с условными данными и датой из макетов; они не входят в production-сборку. В обычном приложении подмены API нет.

## Частые вопросы

- **`docker` не распознан или Docker daemon недоступен:** установите и запустите Docker Desktop, дождитесь его готовности, перезапустите терминал.
- **Порт `3000` занят:** остановите старый `npm run dev` или предыдущий frontend-контейнер. В проекте фиксированный порт, автоматического переключения нет.
- **Страница открылась, но вход не работает / в логах `ECONNREFUSED`:** проверьте `http://localhost:8000/docs`, логи backend и `DOCKER_BACKEND_URL`. Для backend вне Docker проверьте запуск с `--host 0.0.0.0`.
- **Не видны изменения исходников:** выполните `docker compose up --build -d` из папки frontend.
- **В backend сообщения о пустых `POSTGRES_*`:** проверьте `.env` в папке backend и используйте реквизиты существующей базы. Удалять том PostgreSQL для исправления подключения не требуется.

## Git и размещение

В Git нужно добавить `Dockerfile`, `.dockerignore`, `compose.yaml`, `.env.example`, README и исходники. `.env`, `node_modules/` и `dist/` в Git не добавляются. Правила веток — в [CONTRIBUTING.md](CONTRIBUTING.md).

Этот Dockerfile запускает Vite в режиме разработки. Для production нужны сборка `dist/`, веб-сервер с возвратом `index.html` для маршрутов приложения и настроенный reverse proxy к API. `npm run preview` предназначен для просмотра сборки и не использует dev-прокси `/backend`.
