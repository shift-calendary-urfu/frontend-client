# Отчёты по сменам

## Переходы и период

В календаре ссылка «Отчёт за месяц» передаёт выбранные ПВЗ и месяц. Ссылка «Отчёт по сменам» в карточке ПВЗ открывает форму с текущим месяцем. Переходы доступны владельцу и активному администратору этой точки.

Страница находится по адресу `/reports/monthly?workplace=11&month=2026-11`. Ссылка с месяцем сразу загружает отчёт. При открытии из карточки ПВЗ выберите период и нажмите «Сформировать отчёт». Кнопки «Этот месяц» и «Прошлый месяц» помогают выбрать период.

Backend формирует отчёт за один календарный месяц. Допустимы месяцы с января 2000 по декабрь 2100 года включительно. Выбранный период сохраняется в адресе страницы и восстанавливается после перезагрузки. Кнопка «К календарю» возвращает к тому же ПВЗ и месяцу.

## Показатели

Итоги и строки сотрудников берутся из ответа сервера.

| Поле API | Отображение |
| --- | --- |
| `total_hours` | Всего часов по ПВЗ |
| `total_shifts` | Всего смен по ПВЗ |
| `full_name` | Полное имя сотрудника |
| `hours_worked` | Все часы сотрудника за месяц |
| `full_shifts_count` | Полные смены сотрудника |
| `full_shifts_hours` | Часы в полных сменах сотрудника |

Карточка «Полных смен» показывает сумму `full_shifts_count` по сотрудникам. На телефоне строки таблицы превращаются в компактные карточки с подписями показателей.

По правилам backend полная смена начинается до открытия ПВЗ или одновременно с ним и заканчивается после закрытия или одновременно с ним. Учитывается вся длительность такой смены. Отменённые и удалённые смены исключены. Активные сотрудники без смен отображаются с нулями. Смены бывших сотрудников за выбранный месяц также входят в отчёт.

## API и Excel

Контракт проверен по коду присланного backend и `docs/openapi_15112026.json`.

| Действие | Метод и путь |
| --- | --- |
| Сформировать и просмотреть отчёт | `GET /shifts/reports/calendar` |
| Скачать Excel | `GET /shifts/reports/calendar/excel` |

Оба запроса содержат Bearer-токен и query-параметры `workplace_id`, `month`, `year`. В браузере перед путём стоит префикс `/backend`, который убирает прокси Vite.

Excel скачивается с сервера как бинарный файл с именем `report_<workplace_id>_<YYYY-MM>.xlsx`. Файл создаёт backend. Клиент проверяет успешность ответа, MIME-тип и непустое содержимое, затем передаёт файл браузеру. Для выгрузки используется общий механизм обновления access-токена при 401.

Если пользователь меняет месяц, старый результат и кнопка скачивания скрываются до формирования нового отчёта. При смене ПВЗ повторно проверяются права. Поздний ответ предыдущего запроса не заменяет новый результат. Ошибка скачивания оставляет отчёт доступным для повторной попытки. Месяц без смен можно просмотреть и выгрузить.

Данные рассчитываются по актуальному расписанию при каждом запросе. После изменения смен нажмите «Обновить отчёт».

## Проверки

Компонентные тесты `tests/reports.test.tsx` проверяют параметры запросов, права владельца и администратора, смену периода, ошибки и бинарную выгрузку с обновлением токена.

Браузерные сценарии `tests/reports.spec.ts` проверяют переходы, сохранение периода, пустой месяц, адаптацию к экранам от 320 px и получение Excel без изменения его байтов. Файл `tests/fixtures/report.xlsx` создан генератором из присланного backend и используется только в тестах.

Запуск проверок из корня frontend:

```powershell
npm.cmd test
npm.cmd run build
npx.cmd playwright install chromium
npm.cmd run test:e2e
```

В Bash используйте `npm` и `npx`. Для ручной проверки войдите владельцем, откройте ПВЗ со сменами, сформируйте отчёт и сравните часы и полные смены с содержимым скачанного Excel. Отдельно проверьте месяц без смен и доступ администратора другой точки.
