# Календарь и расписание сотрудников

Реализация опирается на `openapi_231026.json` и код `app/shifts` из присланной версии backend-server. Установка дополнительных зависимостей для календаря не нужна. Docker и локальный запуск остаются прежними: см. [README](../README.md).

## Выполненные задачи

1. Календарь месяца получает смены из API, показывает дни недели с понедельника и смены цветными блоками с именами. Полное имя и время доступны в подписях для вспомогательных технологий и на экране дня. Можно выбрать ПВЗ, перейти к предыдущему, следующему или текущему месяцу и открыть день.
2. Создание смены: активный сотрудник выбранного ПВЗ, дата выбранного дня, начало, конец и необязательное примечание.
3. Редактирование смены: изменение начала и конца; сотрудник, дата и примечание остаются прежними согласно `ShiftUpdate`.
4. Удаление отдельной смены. Если у сотрудника несколько смен за день, дополнительно доступно удаление всего его расписания за этот день.
5. Удаление всех смен всех сотрудников выбранного ПВЗ за день одним запросом.
6. Копирование всех или отдельных смен исходного дня на несколько выбранных дат, в том числе из разных месяцев. До отправки показано число будущих копий; после ответа показано фактическое число из API.

Календарь открывается через нижнее меню и из описания рабочей точки. После изменений данные повторно загружаются с сервера. В продукте нет встроенных демонстрационных данных: тестовые ответы находятся только в `tests/`.

## Оформление по макетам

- Месяц показывает год и до трёх смен на дату. Счётчик «+N» указывает, сколько ещё смен видно в расписании дня. Подписи дней недели и навигация по месяцам остаются над сеткой при прокрутке.
- В панели дня видны полное имя и время каждой смены. Цветной отрезок показывает её положение на шкале, а нажать можно на всю строку. Заголовок панели с кнопкой «Закрыть» остаётся видимым при прокрутке.
- Создание: «Добавить сотрудника» в панели дня назначает смену существующему сотруднику. Сотрудник выбирается в нижней панели. Для начала и конца смены прокрутите часы и минуты, затем нажмите «Готово». Примечание можно добавить под раскрывающимся пунктом.
- Редактирование: нажатие цветной полосы открывает форму поверх месяца. В ней доступны «Сохранить» и «Удалить» с подтверждением. Примечание существующей смены доступно для чтения.
- В панели копирования исходные смены выбираются в раскрывающемся списке. Число выбранных смен, дат и будущих копий видно над кнопкой «Сохранить». Выбранные даты сохраняются при переключении месяца.
- «Удалить смены» в панели дня удаляет весь день. Если у сотрудника несколько смен, удаление всех его смен за день находится в «Дополнительно».
- Панели закрываются кнопкой, нажатием затемнённой области или Escape, когда нет активного запроса. Фокус клавиатуры удерживается внутри открытой панели; фон заблокирован. Подтверждение удаления временно блокирует нижнюю панель.

Страница и нижние панели занимают доступную ширину до 600 px и центрируются на широких экранах. Сетка меняет высоту строк в зависимости от высоты экрана. Длинный заголовок ПВЗ сокращается многоточием, а полный адрес виден в прокручиваемом списке «Выбрать». Нижние панели и экран копирования учитывают безопасные отступы устройства.

Дата, имя и время берутся из API и текущего выбора. Надпись «Сегодня» используется только для фактической текущей даты. Назначение дней, типы полей и ограничения времени определяет контракт backend.

## Страницы

Во всех ссылках на день и формы обязателен query-параметр `workplace` — ID ПВЗ.

| URL                                                | Назначение                                                            |
| -------------------------------------------------- | --------------------------------------------------------------------- |
| `/calendar?workplace=11&month=2026-10`             | Месяц; без параметров выбираются первый доступный ПВЗ и текущий месяц |
| `/calendar/2026-10-23?workplace=11`                | Нижняя панель дня со шкалой смен сотрудников                          |
| `/calendar/2026-10-23/shift/add?workplace=11`      | Создание смены                                                        |
| `/calendar/2026-10-23/shift/301/edit?workplace=11` | Редактирование смены с ID 301                                         |
| `/calendar/2026-10-23/duplicate?workplace=11`      | Копирование смен исходного дня                                        |

Даты в таблице — примеры адресов. В интерфейсе работают выбранные пользователем даты. Нижнее меню видно в календаре месяца и скрыто при открытии дня, создания, редактирования и копирования, как в макетах.

## Запросы к API

Ниже указаны пути backend. В браузере к ним добавляется `/backend`, который удаляет прокси Vite. Префикс `/api/v1` не используется. Каждый запрос содержит Bearer-токен и `workplace_id` выбранной точки.

| Действие           | Запрос                      | Параметры или JSON                                                                    |
| ------------------ | --------------------------- | ------------------------------------------------------------------------------------- |
| Получить календарь | `GET /shifts/calendar/`     | Query: `workplace_id`, `date_from`, `date_to` включительно                            |
| Получить смены дня | `GET /shifts/`              | Query: `workplace_id`, `date`                                                         |
| Получить смену     | `GET /shifts/{shift_id}`    | Query: `workplace_id`                                                                 |
| Создать смену      | `POST /shifts/`             | Query: `workplace_id`; JSON: `employee_id`, `date`, `start_time`, `end_time`, `notes` |
| Изменить время     | `PUT /shifts/{shift_id}`    | Query: `workplace_id`; JSON: `start_time`, `end_time`                                 |
| Удалить смену      | `DELETE /shifts/{shift_id}` | Query: `workplace_id`                                                                 |
| Удалить весь день  | `DELETE /shifts/`           | Query: `workplace_id`, `date`                                                         |
| Скопировать смены  | `POST /shifts/duplicate/`   | Query: `workplace_id`; JSON: `shift_ids: number[]`, `dates: string[]`                 |

`employee_id` — ID записи сотрудника в ПВЗ (`Employee.id`), а не ID аккаунта (`user_id`). Список доступных точек берётся из `GET /workplaces/`, сотрудники и права — из `GET /workplaces/{id}`, текущий пользователь — из `GET /users/me`.

В API нет отдельного удаления всех смен одного сотрудника за день: интерфейс последовательно удаляет его смены этого дня по ID. При частичной ошибке показывается число успешно удалённых смен и заново загружается фактический список. Расписания других сотрудников не удаляются.

## Права и состояния

- Просмотр — владелец и сотрудники доступного ПВЗ.
- Создание, изменение, удаление и копирование — фактический владелец (`Workplace.owner_id`) или активный сотрудник этого ПВЗ с ролью `admin`. Надпись `owner` в записи сотрудника сама по себе не даёт владения.
- Прямые ссылки на формы также проверяют права. Окончательное решение о доступе принимает backend.
- Доступны загрузка, пустой месяц или день, ошибка с повторной загрузкой, успешный результат операции.
- Только предусмотренный backend ответ 404 `Shifts not found or not active…` преобразуется в пустой месяц или день. Другие 404 остаются ошибками; при получении отдельной смены 404 не скрывается.
- Подтверждение требуется для каждого удаления. Во время запроса форма или диалог заблокированы; повторное нажатие не отправляет вторую запись.
- При ошибке сохранения введённые данные остаются в форме. Сессия обновляется существующим общим API-клиентом; при её окончании открывается вход.
- Ответы от предыдущего месяца или ПВЗ игнорируются после переключения. Неверные даты и номера в URL не отправляются в API смен.

## Ограничения текущего API

- Входное время — `HH:MM`, только `:00` или `:30`; конец строго позже начала. Ночные смены через полночь не поддерживаются.
- Даты передаются как `YYYY-MM-DD` без преобразования в UTC. Время отображается как заданное для ПВЗ, без пересчёта между часовыми поясами.
- При редактировании API принимает только время. Для другого сотрудника или даты нужна новая смена.
- Копирование сохраняет сотрудника, время и примечание. Выбранные даты уникальны; исходный день исключён из выбора.
- Backend добавляет новые записи без проверки пересечений и без замены существующих смен. Это поясняется перед копированием. После сетевой ошибки записи перед ручным повтором следует проверить календарь: сервер мог успеть сохранить данные.
- Автоматическое составление графика, учёт фактических выходов, отчёты, чат, уведомления и PWA в этот этап не входят.

## Проверка перед сдачей

1. Запустить актуальные backend и frontend по README. Зарегистрировать отдельные аккаунты владельца и сотрудника. Добавить сотрудника в ПВЗ.
2. Открыть календарь нужного ПВЗ. Проверить пустой месяц и переход между месяцами, включая декабрь — январь и февраль високосного года.
3. Создать смену сотруднику. Обновить страницу: запись должна загрузиться с сервера. Изменить время, проверить сохранение.
4. Создать сотруднику вторую смену в тот же день. Отдельно проверить удаление одной смены и всего расписания этого сотрудника за день, включая отмену. Смены других сотрудников должны сохраниться.
5. Скопировать выбранные смены на две даты из разных месяцев. Проверить сохранение времени и примечания, а также сохранение уже существующих смен.
6. Удалить весь день с подтверждением. Проверить, что записи других дат и другого ПВЗ сохранились.
7. Войти обычным сотрудником, затем администратором. Проверить просмотр, разрешённые действия и прямые ссылки на формы.
8. Проверить календарь, форму и копирование на телефоне; отключить API и проверить сообщение об ошибке и повторную загрузку.

Автоматические проверки запускаются командами `npm test`, `npm run build` и `npm run test:e2e`. Для Playwright предварительно требуется `npx playwright install chromium`. В PowerShell при необходимости используйте `npm.cmd` и `npx.cmd`.

Тесты используют подменённые HTTP-ответы: это проверка frontend, а не проверка развёртывания backend, миграций и PostgreSQL. Перед сдачей необходим сценарий выше с реальным API.

### Результаты проверки этой версии

- `npm test`: прошли 85 тестов, включая запросы смен, права, выбор времени и смену пароля.
- `npm run build`: проверка TypeScript и сборка Vite прошли.
- `npm run test:e2e`: в Chromium прошли 14 сценариев с подменёнными ответами API, в том числе плотный календарь, получасовые смены, длинные поля и блокировка прокрутки при удалении.
- Совместный запуск с FastAPI и PostgreSQL и проверка на физических телефонах остаются отдельными проверками.

Для ручного сравнения есть изолированные страницы `/tests/visual/calendar-host.html?screen=calendar` (также `day`, `add`, `edit`, `copy`). Открывайте их через dev-сервер. Они используют только тестовые ответы, условных сотрудников и дату 28 января 2025 года. Изображение телефона и системные индикаторы не добавляются; тестовая страница задаёт только отступы и размер 393 × 852. В production эти страницы не собираются.
